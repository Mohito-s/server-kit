# server-kit

Подготовка чистого Ubuntu/Debian сервера одной командой. Всё на русском, с пояснениями для новичков.

## Какой сервер подойдёт
- **ОС:** Ubuntu 22.04 / 24.04 или Debian 11 / 12 (лучше чистая, только что установленная)
- **Тип:** KVM-виртуалка. На OpenVZ/LXC файрвол может не работать
- **Базовый набор:** от 1 ядра, 1 ГБ памяти, 10 ГБ диска
- **С Docker:** от 2 ГБ памяти и 20 ГБ диска
- **Docker + Netdata + сайты/боты/Remnawave на том же сервере:** лучше 4 ГБ памяти
- **Процессор:** x86_64 или ARM64. Нужны root, systemd и интернет
- Цифры примерные. Скрипт сам проверяет сервер перед установкой и предупредит, если ресурсов мало.
  Справка прямо на сервере: `bash install.sh --help`

## Установка
1. На чистом сервере под root:
```
curl -fsSL https://raw.githubusercontent.com/Mohito-s/server-kit/main/install.sh | bash
```
Скрипт покажет, что он умеет, проверит сервер, задаст вопросы и спросит подтверждение.
Токен бота и chat id сохраняются только на сервере (`/etc/server-kit/config.env`, доступ только root).
Секретов в репозитории нет, он публичный.

Без вопросов:
```
curl -fsSL https://raw.githubusercontent.com/Mohito-s/server-kit/main/install.sh \
 | YES=1 TG_TOKEN=123:abc TG_CHAT_ID=12345 WITH_BOT=1 WITH_DOCKER=1 WITH_NETDATA=0 bash
```

## Токен и chat id
- Токен: Telegram → @BotFather → /newbot. **Заведи отдельного бота для сервера**, не того, что уже работает в проекте.
- Chat id: напиши @userinfobot, он ответит твоим id.
- Нажми Start у своего бота, иначе он не сможет писать тебе.

## Что делает каждый модуль
| Модуль | Простыми словами |
|---|---|
| base | ставит нужные программы, включает автообновления безопасности |
| alerts | пишет в Telegram, когда кто-то заходит по SSH |
| firewall | «забор»: открыты только SSH, 80 и 443 (+ `EXTRA_PORTS`) |
| crowdsec | «охранник»: банит подбор паролей и сканирование портов, пишет тебе |
| access | страховка доступа: запасной ключ, защита SSH от поломки, команда `kit-access` |
| backup | автобэкап по воскресеньям настроек, SSH-ключей и баз в Telegram + `kit-restore` |
| friends | раздача AmneziaWG друзьям: генерация QR и безопасный сплит (без слива IP в Госуслуги) |
| bot | команды из Telegram: `/menu`, `/status`, `/unban`, `/repair`, `/backup`, `/friends` |
| docker | (по желанию) запуск сервисов в контейнерах, нужен для Remnawave |
| netdata | (по желанию) графики нагрузки, только через SSH-туннель |
| audit | проверка здоровья каждые 10 минут, оценка безопасности раз в неделю |

## Если потерял доступ к серверу
Как это решают девопсы, от простого к сложному:
1. **Вход по запасному ключу.** Поэтому скрипт просит добавить второй ключ при установке.
   Добавить позже: `kit-access add-key "ssh-ed25519 AAAA..."`.
2. **Забанили твой IP (сменился адрес, ошиблись паролем).** Напиши боту `/unbanall`
   или `/unban 1.2.3.4`. Снять бан можно и с телефона.
3. **SSH сломался** (после перезагрузки не стартует, кто-то испортил конфиг). Напиши боту `/repair`.
   Он создаст папку `/run/sshd`, вернёт последний рабочий конфиг, откроет порт и перезапустит SSH.
   Постоянная защита от этой поломки ставится при установке.
4. **Нет ни ключа, ни пароля.** Бот и скрипты тут не помогут, и это правильно: иначе так мог бы
   войти и злоумышленник. Заходи через **консоль (VNC) в панели хостера** или режим **Rescue**,
   там можно сбросить пароль root. Потом: `kit-access add-key "..."` и `kit-access repair`.

Бот намеренно не умеет добавлять ключи и менять пароли. Он отвечает только на твой chat id.
Если украдут токен бота, без твоего Telegram-аккаунта команды выполнить всё равно не получится.

Команды на сервере: `kit-access status | backup | add-key | unban | unbanall | repair | help`.
Копия настроек доступа лежит в `/root/kit-backups` (внутри секреты, никому не отправляй).

## Другие команды
- `kit-check` — самопроверка всех служб прямо сейчас; `kit-audit` — аудит безопасности Lynis
- `kit-backup` — создание архива и отправка в Telegram; `kit-restore <файл>` — восстановление из архива
- `cscli decisions list` — кто забанен; `cscli metrics` — статистика CrowdSec
- Netdata: `ssh -L 19999:localhost:19999 root@СЕРВЕР`, затем http://localhost:19999

## Важно
- Пароли и порт SSH скрипт не меняет. Отключать вход по паролю стоит вручную, когда вход по ключу проверен.
- Если UFW уже включён, правила не меняются, добавляется только SSH.
- Дополнительные порты (Remnawave, ноды): `EXTRA_PORTS="8443/tcp 2222/tcp"`.
- Docker обходит UFW: порты контейнеров публикуй как `127.0.0.1:8080:8080` и пускай через Nginx.
- Твой IP на момент установки попадает в whitelist CrowdSec, чтобы не забанить себя.
- Скрипт защищает сервер от взлома, но не скрывает VPN от ТСПУ: для этого нужны Reality/XHTTP/CDN.
- Сначала проверь на новом дешёвом сервере, потом на боевом.

## Docker Compose в двух словах
Файл `docker-compose.yml` описывает, какие программы запустить. `docker compose up -d` запускает,
`docker compose ps` показывает статус, `docker compose logs -f` — логи, `docker compose down` останавливает.
